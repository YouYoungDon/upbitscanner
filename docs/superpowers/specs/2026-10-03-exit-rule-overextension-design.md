# 과열 필터 + 일반픽 청산 레벨 설계

**작성:** 2026-10-03
**상태:** 설계 승인 (구현 전)
**동기:** 사용자 관찰 — "항상 급등하면 그 뒤에 캐치하는 것 같다"

---

## 1. 배경 — 관찰을 측정으로 검증

사용자가 스캐너 방향성에 의문을 제기했다: 픽이 항상 급등 **뒤에** 잡히는 느낌. 감으로 답하지 않고 스코어카드에 기록된 실제 픽 1,557건(2026-06-11~09-22, 256마켓)의 **진입 전 상승폭**을 측정했다.

### 1.1 평균적으로는 급등 추격이 아니다

| 진입 전 상승폭 | 평균 | 중앙값 |
|---|---|---|
| 직전 3일 | +2.6% | -0.2% |
| 직전 7일 | +1.7% | -0.8% |
| 직전 20일 | 0.0% | -5.5% |

전형적인 픽은 진입 시점에 오히려 약간 하락한 상태다. 구조적 펌프 추격은 아니다.

### 1.2 그러나 과열 구간이 실재한다 (뒤집힌 U자)

진입 전 7일 상승폭 구간별 → 진입 후 7일 성과:

| 진입 전 7일 | n | 승률 | 평균 | 중앙값 |
|---|---|---|---|---|
| 급락 후 (-10%↓) | 329 | 50% | +1.2% | +0.5% |
| 약세 (-10~0%) | 472 | 48% | +1.5% | -0.2% |
| 완만상승 (0~10%) | 421 | 49% | +3.3% | 0.0% |
| **상승 (10~30%)** | 260 | **59%** | **+6.1%** | **+3.3%** |
| **급등 후 (+30%↑)** | **75** | **35%** | **-2.0%** | **-6.2%** |
| *전체 기준선* | *1,557* | *50%* | *+2.5%* | *+0.1%* |

선형 상관계수는 pre7 vs fwd7 = **-0.010**(거의 0). 단순 상관만 봤다면 "관계 없음"으로 오결론했을 것이다. 구간 분해가 비선형 구조를 드러냈다.

### 1.3 임계값 단조성 — 절벽이 아니라 기울기

| 임계 | n | 승률 | 평균 | 중앙값 |
|---|---|---|---|---|
| >20% | 159 | 43% | +2.1% | -1.5% |
| >25% | 112 | 38% | +1.1% | -1.6% |
| >30% | 75 | 35% | -2.0% | -6.2% |
| >35% | 59 | 32% | -5.1% | -8.2% |
| >40% | 39 | 26% | -5.5% | -8.9% |
| >50% | 26 | 19% | -10.2% | -13.7% |

여섯 지점에서 **일관된 악화**. 단일 컷오프가 운좋게 맞은 것이 아니라는 강한 신호이며, argmax 한 점보다 신뢰할 수 있는 근거다.

### 1.4 기존 추격감점은 잘못된 변수를 쓰고 있다 (결정적 테스트)

`lib/buy-modifiers.mjs`에 이미 추격감점이 있다:
```js
if (volRatio != null && volRatio >= 5 && !pump) { score *= 0.8; sig.push('⚠️추격주의(급등후)') }
```
의도는 동일(추격 방지)하지만 **거래량 비율**로 측정한다. 가격 과열(runUp7>30%)과 2×2로 분해:

| 칸 | 조건 | n | 승률 | 중앙값 |
|---|---|---|---|---|
| A | 라벨 + 가격과열 | 34 | **24%** | **-8.2%** |
| B | **라벨만** (거래량↑, 가격 미상승) | **126** | **55%** | **+1.3%** |
| C | **과열만** (라벨 없음, 기존이 놓침) | 41 | 44% | -2.2% |
| D | 둘 다 아님 | 1,356 | 50% | +0.3% |

**결론:**
- **B(라벨 픽의 79%)는 기준선보다 우수**한데 ×0.8 감점을 먹고 있다 → 기존 감점은 **역효과**
- 나쁜 집합은 A(겹침)와 C(기존이 완전히 놓침)
- 분류기 성능: 과열 포착률(recall) **45%**, 정밀도(precision) **21%**

"감점이 나쁜 픽을 이미 걸러서 평범해 보이는 것"이라는 선택편향 가설은 **기각**됐다. 살아남은 라벨 픽은 평범이 아니라 우수하다.

**남는 불확실성(명시):** B의 55%는 감점을 먹고도 문턱을 넘은 픽 기준이다. 감점 제거 시 현재 문턱 아래로 밀려난 거래량급증 픽이 추가 유입되는데, 그 신규 유입분의 성과는 이 표본으로 알 수 없다. → 출시 후 거래량급증 모집단 성과를 모니터링한다.

### 1.5 최대 구멍은 진입이 아니라 청산

| | MFE(최대상승) | 종가 | 포기율 |
|---|---|---|---|
| +1일 | +6.2% | +0.6% | **90%** |
| +7일 | +16.5% | +2.4% | **85%** |

픽이 평균 +6.2% 치솟고 +0.6%로 마감한다. 유리한 움직임의 90%를 반납한다. 현재 일반 매수픽에는 청산 지침이 **전혀 없다**(🎯조용한바닥 픽만 SL/TP 보유).

## 2. 목표 / 비목표

### 목표
1. **과열 필터** — 가격 상승폭 기준 2단 등급 감점으로 측정된 마이너스 엣지 제거. 잘못 측정하던 volRatio 추격감점을 대체.
2. **일반픽 청산 레벨** — 모든 매수픽에 백테스트로 검증된 손절/목표가를 계산·기록·표시.
3. **측정 가능성** — 스코어카드가 청산 규칙 성과를 채점해 "실제로 먹을 수 있었나"를 수치화.

### 비목표 (YAGNI)
- **포지션 추적·청산 알림 없음.** 픽에 수치 표시만. `positions.json` 연동, 보유 상태 관리, 중복 알림 방지는 범위 밖(별건).
- **스웟스팟 가산 없음.** 10~30% 구간이 59%/+3.3%로 우수하지만 가산(mult>1)은 과적합 위험이 더 크고 점수 상한·티어 해석에 연쇄 영향. 감점만 한다.
- **과열 구간 제외(mult 0) 없음.** n=75에 35% 승률은 "아예 없다"고 하기 어렵다. 감점으로 처리.
- **momentum-scan·flow-scan 미적용.** 근거: `appendScan`은 `monitor.mjs`만 호출하므로 두 스캐너 픽은 아카이브되지 않고, 각자 로그는 30스캔 롤링이다. **검증 자체가 불가능**하다. 아카이빙 선행이 필요한 별건. (이벤트 방어는 3개 전부에 걸었으나 "상폐는 어디서든 상폐"라 외삽이 안전했다. 과열 효과는 픽 모집단에 의존해 외삽이 위험하며, momentum-scan은 추세지속이 설계 목적이라 상승폭 분포가 구조적으로 다르다.)

## 3. 설계

### 3.1 과열 필터

**측정 변수**
```
runUpPct = (최근 확정종가 / lookback봉 전 확정종가 - 1) × 100
```
순수 헬퍼 `calcRunUpPct(closes, lookback)`를 `lib/indicators.mjs`에 추가(`calcRSI`·`calcVolRatio`와 동일한 자리·스타일).

**배선**
`scripts/monitor.mjs`가 스코프에 이미 있는 `confirmed`에서 계산해 `ctx.runUpPct`로 전달(`volRatio`·`circRatio`와 동일한 스칼라 패턴). `lib/buy-modifiers.mjs` 체인에 과열 스텝 추가 — 체인은 순서가 의미를 갖는 구조이며 기존 추격감점 자리를 차지한다.

**기존 감점 대체 (병존 아님)**
`volRatio >= 5` 추격감점과 `&& !pump` 면제를 **제거**한다.
- 같은 의도를 두 변수로 이중 감점하는 것을 피한다. 이 코드베이스에 전례가 있다: 업비트 유의지정이 구조리스크 ×0.9와 이벤트 ×0.5로 이중 감점(×0.45)되던 버그 → 억제로 수정.
- `!pump` 면제는 *"volRatio가 정당한 펌프 시작에도 터지니까"* 끼운 우회였다. 가격 상승폭으로 바꾸면 불필요해진다: Pump Start는 정의상 초기라 상승폭이 작아 걸리지 않고, 거꾸로 "이미 +35% 오른 상태의 Pump Start"는 후기 펌프이므로 **걸러야 맞다**. 올바른 변수는 특수 케이스를 없앤다.

**2단 등급 감점** (효과가 단조롭기 때문에 단일 컷오프보다 적합)
```
runUpPct > tier2Pct → score *= tier2Mult, 라벨 '⚠️과열(7일 +NN%)'
runUpPct > tier1Pct → score *= tier1Mult, 라벨 '⚠️과열주의(7일 +NN%)'
그 외 → 변화 없음
```

**파라미터 사전등록(pre-registered) 선정 규칙** — argmax 금지

과열 구간은 전체의 5%(75건)뿐이어서 아웃오브샘플 검증이 불가능하다(§3.3.3). argmax 선정은 과적합의 교과서다. 따라서 **값을 고르는 규칙을 먼저 고정**한다:

1. 학습 구간에서 단조성(임계 상승 → 승률 하락)이 성립하는지 확인. **성립하지 않으면 과열 필터 전체를 보류**한다.
2. `tier1Pct` = 중앙값 fwd7 ≤ **-1.0%** 이고 n ≥ **60**인 **가장 작은** 임계값
3. `tier2Pct` = 중앙값 fwd7 ≤ **-8.0%** 이고 n ≥ **30**인 **가장 작은** 임계값
4. 배수는 피팅하지 않고 "약한 감점" 원칙으로 **고정**: `tier1Mult = 0.85`, `tier2Mult = 0.60`
5. `lookback` = **7**(일). 3/14일도 리포트하되 7일을 기본으로 둔다 — §1.2 효과가 7일에서 측정됐고, lookback까지 피팅하면 자유도가 늘어난다.

현재 전체 표본 적용 시 예상값: `tier1Pct ≈ 20`(>20%: n=159, 중앙 -1.5%), `tier2Pct ≈ 35`(>35%: n=59, 중앙 -8.2%). **최종값은 학습 구간 기준으로 확정**한다.

**적용 범위:** `monitor.mjs`만 (§2 비목표 참조).

### 3.2 일반픽 청산 레벨

**핵심 분리: 기록과 표시를 분리한다.**

**① 기록 — 모든 매수픽에 부착**
```
item.exit = {
  slPct, tpPct, holdMax,        // 적용된 파라미터(스탬핑)
  stopLoss, takeProfit,          // 풀 정밀도 가격
  cfgVersion                     // 예: 'general-exit-v1'
}
```
표시 여부와 무관하게 **전 매수픽에 기록**한다. 스코어카드가 청산 규칙 성과를 모집단 전체에서 **균일하게** 측정해야 하므로, 표시되는 픽만 기록하면 측정이 조각난다.

**② 표시 — 기존 우선순위 체인에 맨 뒤 폴백으로 추가**

`monitor.mjs`의 현재 체인(라인 267-269)은 구체성 순서다:
```
strategy(조용한바닥: SL+TP) → vbottomSL(SL만) → pumpSL(SL만) → [신규] exit(SL+TP)
```
`vbottomSL`·`pumpSL`은 **가격 구조에서 유도된 손절**이라 일반 %보다 정보량이 많다. 따라서 일반 레벨은 최하위 폴백이다.

**레벨 세트를 섞지 않는다.** "V바텀의 구조적 손절 + 일반 목표가" 조합이 더 유용해 보이지만, `(slPct, tpPct)`는 백테스트에서 **쌍으로 최적화**된 값이다. 손절만 교체하면 그 목표가의 검증 근거가 사라진다. 각 세트의 내부 일관성을 지킨다. V바텀 픽에 목표가가 없는 것은 현상 유지이며 회귀가 아니다.

**③ 설정 파일 분리 — `data/exit-config.json`**

`strategy-config.json`에 중첩하지 않는다. 결정적 이유: `scripts/strategy-backtest.mjs`가 그 파일을 `writeJson`으로 **통째로 덮어쓴다**. 일반 파라미터를 중첩하면 조용한바닥 백테스트 실행 시마다 소실된다. 별도 파일이면 두 백테스트가 독립적 수명을 갖는다.

스키마 (`exit-backtest.mjs`가 생성하는 산출물 — 값은 §3.3.5 선정 기준의 결과이며 사람이 손으로 쓰지 않는다):
```
version     string   고정 'general-exit-v1'
confirmedAt string   ISO8601 생성 시각
slPct       number   손절 % (양수) — 그리드 [5,7,10,12] 중 선정
tpPct       number   목표 % (양수) — 그리드 [6,8,12,18,25] 중 선정
holdMax     number   최대 보유 봉수 — 그리드 [3,5,7] 중 선정
```
`strategy-config.json`과 동일하게 **git 커밋**한다(감사 가능성). 과열 필터 파라미터(`lookback`/`tier*Pct`/`tier*Mult`)는 §3.1에서 사전등록 규칙으로 고정되므로 이 파일이 아니라 `buy-modifiers.mjs`의 명명 상수로 둔다 — 백테스트가 자동 갱신하는 값이 아니기 때문이다.

**④ 정밀도 — 풀 정밀도 저장, 표시에서만 포맷**

`monitor.mjs:132` 주석이 명시 경고한다: *"0.0x원대 코인에서 toFixed(2)는 손절=목표로 붕괴."* 소폰(5.2원)이 정확히 이 케이스다. `item.exit`에는 풀 정밀도를 저장하고 포맷은 표시 시점에만 적용한다.

**⑤ cfgVersion 스탬핑 — 과거 소급 재작성 방지**

픽에 `cfgVersion`과 파라미터를 함께 기록한다. 없으면 exit-config 갱신 시 과거 픽의 "먹었을 수익"이 소급 변경되어 성과 비교가 깨진다.

**⑥ 설정 부재 시 — 스캔 불사침**

`exit-config.json`이 없으면 일반 레벨만 조용히 생략하고 스캔은 정상 완료한다(`monitor.mjs:127`의 `if (strategyConfig)` 패턴, 이벤트 레이어의 중립 폴백 원칙과 동일).

**재사용:** 레벨 계산은 `strategyLevels(price, { slPct, tpPct })` 그대로 사용. 새 수식 없음.

### 3.3 파라미터 검증

#### 3.3.1 리플레이 하네스 (`scripts/exit-backtest.mjs`)

기록된 스코어카드 에피소드 + 일봉으로 그리드를 돌린다. 조합별 산출: 거래수, 승률, 평균수익, 중앙값, 청산사유 분포(tp/sl/time/no-data), MDD/샤프(`lib/perf-metrics.mjs`).

**`scoreStrategyOutcome`을 쓰고 `simulateTrade`를 쓰지 않는다.** 후자는 "신호봉 다음봉 시가" 진입(룩어헤드 방지용 백테스트 관례)이지만, 우리는 **실제로 스캔가에 진입할 수 있었던** 기록된 픽을 리플레이한다. 전자가 맞는 규약이며, 규약을 섞으면 라이브와의 비교성이 깨진다(`lib/strategy.mjs` 주석의 경고).

**그리드**
```
slPct   ∈ [5, 7, 10, 12]
tpPct   ∈ [6, 8, 12, 18, 25]
holdMax ∈ [3, 5, 7]
= 60 조합
```
TP 상단 25%는 MFE7 평균 16.5%를 고려한 탐색 여유이고, 하단 6%는 "빠른 부분익절이 유리"하다는 기존 관측(§1.5, 스코어카드 첫 백필 결론)을 시험하기 위함이다.

`MIN_TRADES = 200`. 모든 에피소드가 거래를 생성하므로 실질 비구속이며, 목적은 대부분이 `no-data`로 해소되는 조합을 배제하는 안전장치다.

#### 3.3.2 출시 게이트 — 현상 유지를 이겨야 한다

비교 기준선은 "청산규칙 없이 7일 종가 보유"다. 측정값(채점완료 1,572건 전체): **승률 50% / 평균 +2.4% / 중앙값 0.0%**.

> §1.2의 *전체 기준선 1,557건 / 평균 +2.5% / 중앙 +0.1%*는 진입전 상승폭 계산이 가능한 부분집합(캔들 20봉 이상 확보)이라 표본이 다르다. **게이트 판정은 반드시 비교 대상과 동일한 에피소드 집합에서 재계산**한다 — 위 숫자를 상수로 하드코딩하지 말고, 백테스트가 같은 집합에서 기준선과 선정값을 **나란히 산출**해야 한다.

선정된 `(slPct, tpPct, holdMax)`가 같은 에피소드 집합에서 이 기준선을 이기지 못하면 **§3.2를 출시하지 않는다.** 판정 지표는 평균수익(1차)과 중앙값(동반 확인) 둘 다 기준선 이상이어야 한다.

**단위 규약 (중요):** 스코어카드의 `ret*`·`mfe*`는 **분수**로 저장된다(`-0.1136` = -11.36%). `exit.ret`도 **동일하게 분수**로 저장한다. 리포트·대시보드 표시에서만 ×100 한다. 이 규약을 어기면 집계가 100배 틀린다(실제 발생한 오류다).

#### 3.3.3 홀드아웃 — 청산은 가능, 과열은 불가능

**청산 파라미터(표본 1,572건): 시간 분할 적용**
- 학습: 2026-06-11 ~ 2026-08-15
- 홀드아웃: 2026-08-16 ~ 2026-09-22
- 약 70/30. 시계열이므로 k-fold는 미래 누출이 발생하여 사용하지 않는다.
- 선정은 학습 구간에서만 하고, 홀드아웃은 **확인용으로 1회만** 본다(홀드아웃을 보고 재선정하면 홀드아웃이 아니다).

**레짐 교란을 함께 보고한다.** 최근 30일 승률 70%는 BTC 강세 순풍 효과다. 홀드아웃이 그 구간에 걸리면 숫자가 부풀어 보인다. 이 프로젝트가 이미 당한 함정이다(조용한바닥 당시: *"post 표본이 약세폭락 주간에 몰려 시장방향과 교란 — 숫자만 보고 결론 금지"*). **학습·홀드아웃 각 구간의 레짐 구성비(bull/bear/중립 일수 비율)를 리포트에 명시**한다.

**과열 임계값: 아웃오브샘플 검증 불가 — 정직하게 명시**

과열 구간이 전체의 5%(75건)뿐이라 어떤 분할에서도 홀드아웃에 ~22건만 남고 검증력이 없다. 홀드아웃을 억지로 만들어 "검증했다"고 주장하지 않는다. 대신:
1. 근거는 **단조성**(§1.3, 여섯 지점 일관 악화)으로 제시
2. 값은 **사전등록 규칙**(§3.1)으로 선정 — argmax 금지
3. 배수는 **약하게 고정**(0.85/0.60) — 틀렸을 때 손해가 작도록
4. **전향 검증 계획**: 출시 후 스코어카드가 계속 채점하므로 2~3개월 뒤 진짜 아웃오브샘플 증거가 축적된다. 그때 재평가한다.

#### 3.3.4 과적합 방어 — 이웃 안정성 검사

그리드 최적 셀을 그대로 쓰지 않고, **인접 셀(각 축 ±1단계, 최대 6개)의 성과를 함께 리포트**한다. 혼자 튀는 봉우리는 과적합 신호이며, 완만한 고원이면 신뢰할 수 있다.

**판정 기준 (구체값):** 최적 셀의 평균수익을 `best`, 인접 셀 평균수익의 중앙값을 `nbr`이라 할 때 —
- `nbr >= best × 0.5` → **안정**. 최적 셀을 채택한다.
- `nbr < best × 0.5` → **불안정**. 리포트에 경고를 표시하고, `평균수익 ≥ 기준선`을 만족하는 셀 중 **인접 안정성 비율(`nbr/best`)이 가장 높은 셀**을 채택한다.

즉 최적값이 인접 대비 2배 이상 튀면 그 봉우리를 믿지 않는다.

#### 3.3.5 선정 기준

1차: `거래수 ≥ MIN_TRADES` 중 **평균수익 최대**(동률 시 승률) — `strategy-backtest.mjs` 선례와 동일하게 유지하여 두 전략 간 비교가능성을 지킨다.
병기: MDD·샤프(`lib/perf-metrics.mjs`)를 함께 보고해 선정값이 리스크 이상치가 아닌지 확인한다.
적용: §3.3.4 이웃 안정성 검사 통과 필수.

#### 3.3.6 과열 필터와 청산의 상호작용

과열 필터는 점수 **감점**이므로 픽 모집단을 부분적으로만 바꾼다(감점 후에도 `BUY_THRESHOLD = 5`를 넘으면 잔존).

따라서 청산 파라미터 선정은 **학습 구간(2026-06-11~08-15)의 모든 픽**을 대상으로 한다 — 과열 픽을 미리 빼지 않는다(프로덕션 모집단이 실제로 그렇기 때문). 그 뒤 **과열 픽을 제외한 부분집합에서 민감도만 확인**한다: 선정값이 해당 부분집합에서도 기준선을 이기면 통과.

> 용어 정리 — 이 절의 "모든 픽 / 부분집합"은 **픽 모집단**(과열 포함 여부)을 뜻하며 **시간 범위가 아니다**. 시간 범위는 §3.3.3이 지배한다: 선정은 학습 구간에서만, 홀드아웃은 확인용 1회.

### 3.4 스코어카드 채점 확장

**에피소드에 필드 추가 (기존 지표 보존)**
```
exit: {
  reason: 'tp' | 'sl' | 'time' | 'open' | 'no-data',
  ret, exitDay,
  cfgVersion,
  cfgSource: 'live' | 'backfill'
}
```
계산은 `scoreStrategyOutcome(ep, confirmed, params, nowMs)` 그대로 재사용 — 새 로직 없음.

**`ret1/ret3/ret7`·`mfe1/mfe3/mfe7`는 변경하지 않는다.** §3.3.2 출시 게이트가 "7일 보유 기준선을 이겨야 함"이므로 그 기준선을 제거하면 판정이 불가능해진다. 순수 추가다.

**파라미터 출처 구분 — 정직성 장치**
- 신규 픽: 픽에 스탬핑된 `item.exit` 파라미터 사용 → `cfgSource: 'live'`
- 기존 1,572건 백필: 스탬프가 없어 현재 config로 소급 계산 → `cfgSource: 'backfill'`

**소급 계산값과 라이브 확정값을 섞어 집계하지 않는다.** 집계·대시보드 노출 시 두 그룹을 분리 표시한다. 섞으면 "우리 규칙이 이만큼 먹었다"는 수치에 소급 보정이 숨는다.

**상태 분리.** 기존 `status`(pending/partial/done/no-data)는 3개 호라이즌이 결정한다. `exit`의 자체 수명(`open`)과 **분리 유지**한다 — 섞으면 기존 집계가 오염된다.

**실행 위치.** `scripts/scorecard.mjs` 배치(매일 KST 09:10, `UpbitScorecard`). 이미 마켓별 일봉을 받으므로 **추가 API 비용 없음**.

## 5. 테스트

`lib/`는 전부 유닛테스트를 보유하며(44개 파일, 559 테스트) `monitor`·스캐너는 무테스트가 이 프로젝트 관례다. 그 관례에 따라 **순수 함수에 테스트를 집중**한다.

**`calcRunUpPct`** (`__tests__/indicators.test.mjs`)
- 정상 계산(상승·하락·무변동)
- 데이터 부족(`closes.length <= lookback`) → `null`
- 기준가 0 또는 음수 → `null` (0 나눗셈 가드)
- `lookback` 경계(1, 배열 길이 - 1)

**`buy-modifiers` 과열 감점** (`__tests__/buy-modifiers.test.mjs`)
- tier1/tier2 경계값(임계 바로 아래·같음·위)
- `runUpPct == null` → 감점 없음
- **`volRatio >= 5`가 더 이상 감점하지 않음**(회귀 방지)
- **`pump: true`가 과열 감점을 면제하지 않음**(면제 제거 확인)
- 라벨 문자열이 `signals`에 추가됨

**스코어카드 청산 채점** (`__tests__/scorecard.test.mjs`)
- `tp`/`sl`/`time`/`open`/`no-data` 각 경로
- 같은 봉 SL·TP 동시 도달 → **손절 우선**(기존 `resolveExit` 정책 승계)
- `cfgSource: 'backfill'` 표시
- 기존 `ret1/3/7`·`mfe` 값이 변하지 않음(순수 추가 보장)

**회귀:** 기존 559 테스트 전부 그린 유지.

## 7. 출시 순서 — 게이트가 앞에 있다

1. `calcRunUpPct` + 테스트
2. **`exit-backtest.mjs` 실행 → 검증 리포트.** **게이트:** §3.3.2 기준선(50% / +2.4% / 중앙 +0.1%)을 이기지 못하면 **3번 이후 전부 중단**. §3.1 단조성이 학습 구간에서 깨지면 과열 필터도 보류.
3. (게이트 통과 시) `monitor.mjs` 기록·표시 + `buy-modifiers.mjs` 과열 감점 배선
4. 스코어카드 청산 채점 + 백필
5. 대시보드 노출

코드를 전부 작성한 뒤 결과를 확인하는 순서가 아니다. 2단계에서 증거가 나오지 않으면 멈춘다. 과열 감점(§3.1)은 단조성 근거로 청산 레벨과 독립 진행 가능하지만, 청산 레벨(§3.2)은 게이트에 걸려 있다.

## 8. 한계 — 결과 보고 시 반드시 동반할 것

1. **표본 3.5개월**(2026-06-11~09-22), 레짐 혼합 한정. 다른 시장 국면에서의 일반화는 미검증.
2. **에피소드 독립성 위반** — 같은 시점·같은 종목이 반복 등장하므로 승률 신뢰구간이 실제보다 낙관적이다. 종목별 클러스터링을 적용하거나, 최소한 이 한계를 명시한다.
3. **과열 임계값은 인샘플**(§3.3.3). 단조성과 사전등록 규칙으로 완화했을 뿐 아웃오브샘플 증거는 아니다. 2~3개월 후 전향 재평가 필요.
4. **기존 추격감점 제거의 2차 효과 미지** — 감점 제거로 신규 유입되는 거래량급증 픽의 성과는 측정 불가(§1.4). 출시 후 모니터링 항목.
5. **순수 TA 엣지는 여전히 ≈0**(전체 승률 50%, 중앙값 +0.1%). 이 설계는 "엣지를 만드는" 것이 아니라 **측정된 마이너스 구간을 제거하고 반납분을 줄이는** 작업이다. 최근 30일 70% 승률은 레짐 순풍이며 실력 향상이 아니다. 성과 보고 시 오버셀 금지.
