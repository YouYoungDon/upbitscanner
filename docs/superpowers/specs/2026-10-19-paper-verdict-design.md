# 모의매매 강화 — 스코어카드 판정 + 무작위 대조 장부 (설계)

작성 2026-10-19. 방안 A(사용자 승인). 판정일 2026-11-05.

## 1. 왜

10-19 기준 모의매매 장부로는 11-05에 어떤 결론도 낼 수 없다.

- 청산 거래 메인 22건(진입일 10일)·모멘텀 16건(8일). 진입일 평균의 일간 흔들림 8~11% →
  거래당 +1% 우위를 t=2로 보려면 메인 약 257일, 모멘텀 약 469일이 필요하다.
- 메인 장부는 자금이 묶여 있다(원장 `no-cash` 58회, 남은 현금 1만 원). 스캔당 메인 픽이 평균 44개인데
  빈 슬롯이 날 때 상위 3개만 산다 — "스캐너 픽의 성적"이 아니라 "자리가 비었던 순간의 픽 성적"이다.
- v2 체결 규칙으로 청산된 거래는 메인 3건·모멘텀 1건.
- 비교 대상이 시장 지수뿐이라, 같은 청산 규칙·비용에서 "고르는 실력"만 떼어 볼 수 없다.

반면 스코어카드(`data/scorecard.json`)는 메인 픽 전부를 자금 제약 없이 손절·익절 규칙(12/12/7)으로 채점하고 있다.
10-08 신호 정리 뒤 메인 에피소드 310건(12일). 그래서 **판정은 스코어카드로, 실호가 체결 장부는 비용 보정과 대조로** 역할을 나눈다.

## 2. 불변 조건

- 기존 `main`·`momentum` 장부의 체결·청산 규칙과 `PAPER` 상수는 바꾸지 않는다(11-05까지 규칙 고정).
  `PAPER`가 바뀌면 `paper-trade`가 `modelChanges`를 남기므로, 이 작업 뒤 `modelChanges`가 늘지 않아야 한다.
- 스캐너 점수·픽·알림은 바뀌지 않는다. monitor에는 기록 필드 하나(`universe`)만 더한다.

## 3. 구성

### 3.1 판정 지표 — `lib/verdict.mjs` (순수 함수)

**표본:** 스코어카드 에피소드 중 `entryTs ≥ 2026-10-08T00:00:00Z`, `lowLiquidity` 아님,
`exit.reason ∈ {sl, tp, time}`, `exit.ret`·`exit.exitDay` 유한.
06-11~10-07 에피소드는 같은 계산을 **참고용**으로만 출력한다(판정에 안 씀).

**에피소드 초과수익:** `v = exit.ret − baselineReturn(daily, utcDay(entryTs), exitDay) − cost`.
기준선이 없는 에피소드(null)는 빼고, 뺀 건수를 출력한다.

**비용(cost):** 3.3의 실체결 차이를 쓴다. 짝 표본이 10건 이상이면 `cost = max(−meanGap, 0.001)`
(수수료 0.05%×2보다 낮게 잡지 않는다), 10건 미만이면 기존 판정 원칙의 왕복 0.3%(`0.003`).
어느 값을 썼는지 출력한다.

**t:** 진입일(UTC 일, 09:00 KST 경계) 군집 — 기존 `clusteredT({day, v})`.

**판정 규칙(사전 등록, 11-05 전에 확정):**

| 판정 | 조건 |
|---|---|
| `pass` 통과 | t ≥ 2 **그리고** 전반·후반 평균 모두 > 0 **그리고** 점수 상위 1/3 평균 > 하위 1/3 평균 |
| `fail` 실패 | t ≤ −2 |
| `inconclusive` 판정 불가 | 그 밖(통과 조건 일부만 충족 포함) |

- 전반/후반: 표본의 진입일 목록을 정렬해 가운데 진입일 기준으로 나눈다(기존 paper-report와 같은 방식 — 가운데 날은 후반).
- 점수 구간: 에피소드를 `score` 오름차순으로 정렬해 `k = Math.floor(n/3)`. 하위 = 앞 k개, 상위 = 뒤 k개, 중간 = 나머지.
  구간별 진입일 평균(`clusteredT().mean`)을 비교한다(상위 > 하위). k < 1이거나 상·하위 진입일이 2일 미만이면 조건 불충족.
- 진입일 수가 5일 미만이면 t와 무관하게 `inconclusive`(사유: 표본 부족).
- 판정별 후속(사용자 결정): 통과 → 소액 실전 논의 / 실패 → 반등 매수 신호를 참고용으로 내리고 재설계 /
  판정 불가 → 3.2의 판정 가능 예상일까지 연장.

### 3.2 검정력

- `δ = max(|mean|, 0.005)`, 진입일 평균의 표본 표준편차 `sd`.
- 필요 진입일 수 `need = ceil((2·sd/δ)²)`. `sd`가 없으면(진입일 < 2) null.
- 판정 가능 예상일 = 첫 진입일 + `need`일 + 7일(7일 보유 결과 대기). 이미 `days ≥ need`면 "지금 충분".

### 3.3 실체결 차이 보정

- 메인 장부(`books.main`)의 청산 거래 중 `source === 'main'`과 스코어카드 에피소드를
  **같은 market, `scanAt === Date.parse(ep.entryTs)`** 로 짝짓는다(에피소드 id = `market@timestamp`, 장부 `scanAt` = 같은 스캔 timestamp).
- 짝마다 `gap = trade.net − ep.exit.ret`(장부 순수익은 수수료·스프레드·손절 슬리피지·시간봉 판정 포함, 에피소드는 일봉 원수익).
- 출력: 짝 수, 평균 gap, 진입일 군집 t. 체결 모델별(v1/v2)로도 나눠 보여 준다(판정 cost는 전체 평균).

### 3.4 무작위 대조 장부 `random`

- **monitor:** 스캔 entry에 `universe: string[]` 추가 — 이번 스캔에서 메인 픽이 될 수 있었던 종목.
  `candleMap`에 들어간(일봉 판정이 된) 종목 중 24h 거래대금 ≥ 5억(`LOW_LIQUIDITY_24H`), `warnOf !== 'warning'`인 종목을
  `splitPremiumHot(candidates, kimchi).keep`에 통과시킨 목록(메인 매수 목록과 같은 국내 과열 제외 — 김치프 조회 실패면 아무것도 빼지 않는다).
  순수 함수 `randomUniverse({ markets, tradePrice, warnOf, kimchi })`로 분리한다.
- **paper-trade:** `SOURCES`에 `random` 추가(`file: 'monitor-log.json'`).
  `picksOf(scan) = randomPicks(scan)` — `universe`가 없으면 빈 목록(예전 스캔은 사지 않는다).
  universe를 스캔 timestamp로 시드한 결정적 셔플(mulberry32 + 문자열 해시)로 섞고,
  `{ market, korean_name: null, price: null, score: 0, signals: ['무작위 대조'] }` 픽 목록을 만든다.
  `selectEntries`는 점수가 모두 0이라 안정 정렬로 셔플 순서를 유지한다 — 이미 보유 중인 종목은 거기서 빠진다.
- 규칙은 메인과 같다: `PAPER`의 자본·건당·최대 보유·스캔당 3건, `exitRule(pick, 'random')` → `DEFAULT_RULE`(12/12/7, 메인 general-exit-v1과 같은 값), 체결 모델 v2.
  `PAPER` 상수는 바꾸지 않는다.
- 첫 실행: 기존 로직대로 `book.lastScan`이 없으면 최근 3시간 스캔만 본다.
- **보기:** 대시보드 장부 카드·평가금 곡선 이름표 `무작위 대조`(색 추가), 봇 `모의` 이름표 `무작위 대조`.
- **리포트:** 같은 스캔(`scanAt`)에서 진입한 메인 거래와 무작위 거래를 스캔별 평균 차이(메인 − 무작위)로 묶고,
  진입일 군집 t를 낸다. 보조 지표임을 출력에 명시한다(두 장부 모두 자금 제약으로 표본이 작다).

### 3.5 출력

`npm run paper:report` 맨 위에 "판정" 섹션:
1. 판정 지표(10-08 이후): 건수·진입일 수·평균·t·전/후반·점수 구간 3개·비용 출처 → **판정 결과와 사유**
2. 검정력: 필요 진입일 수·판정 가능 예상일
3. 실체결 차이: 짝 수·평균 gap·t (모델별)
4. 무작위 대조: 메인 − 무작위 스캔 짝 수·평균·t
5. 참고: 06-11~10-07 같은 지표

그 아래 기존 장부별 출력은 그대로(`random` 장부도 같은 형식으로 함께 나온다).

모멘텀은 스코어카드 대상이 아니므로(아카이브가 monitor 전용) 기존처럼 모의매매 장부로만 본다 —
스캔당 픽이 평균 1.1개라 장부가 사실상 픽 전부를 담는다. 표본이 작다는 점을 그대로 출력한다.

## 4. 오류 처리

- 스코어카드·기준선 파일이 없으면 판정 섹션은 "데이터 없음"을 출력하고 기존 리포트는 계속한다.
- 무작위 픽 생성은 `universe`가 배열이 아니면 빈 목록 — 장부 실행을 멈추지 않는다.
- monitor의 `universe` 계산은 기존 값만 쓰므로 새 API 호출·실패 경로가 없다.

## 5. 테스트

- `verdict`: 표본 필터(날짜·저유동성·미청산·기준선 없음), 초과수익 계산, 판정 경계(t=2·−2, 전후반 하나 음수, 점수 구간 역전, 진입일 < 5),
  검정력 수식과 예상일, cost 선택(짝 < 10 → 0.003, 측정값 하한 0.001).
- 짝짓기: market·scanAt 일치만, 모델별 분리.
- 무작위 픽: 같은 timestamp → 같은 순서, 다른 timestamp → 다른 순서, universe 없음 → 빈 목록, 보유 종목 제외(selectEntries 경유).
- 불변 조건: 기존 상태 파일(`params = PAPER`, `fillModel = 2`)을 `loadState` 경로로 읽어도 `modelChanges`가 늘지 않음 —
  `PAPER` 스냅샷 동일성 테스트로 고정.
- monitor `universe`: 순수 함수 `randomUniverse`로 거래대금·경고·과열 제외·김치프 실패 시 무제외를 테스트.
- 봇 `모의` 출력에 `무작위 대조` 이름표.

## 6. 범위 밖

- 실호가 그림자 장부(방안 B), 모멘텀 스코어카드, 대시보드 판정 화면(터미널 리포트만).
- 판정 결과에 따른 자동 동작(신호 끄기 등) — 사람이 결정한다.
